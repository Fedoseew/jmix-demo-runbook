# Подготовка и репетиция

Порядок действий от первой настройки до дня показа. Что делает каждая команда `./demo` — в [Демо A и B → Что подготовить](demos.md#что-подготовить), как вести показ — в [Как вести демо](usage.md). Команды выполняются из папки runbook.

## 1. Один раз заранее

1. Добавить ключ OpenAI в `~/.zshrc` как `SPRING_AI_OPENAI_APIKEY` и проверить, что терминал его видит: `[ -n "$SPRING_AI_OPENAI_APIKEY" ] && echo set`. IntelliJ IDEA читает окружение при старте: после правки `~/.zshrc` её нужно перезапустить.
2. `./demo setup` — worktree `~/IdeaProjects/jmix-crm-stand` на `demo/ai-app`, jar стенда, клон `crm-from-db`, Playwright. Сборка занимает несколько минут.
3. `./demo check` — все строки FAIL исправить по подсказке в самой строке, WARN можно оставить.

## 2. Репетиция демо A

1. `./demo up a`, затем `./demo prepare`: прогрев CRM AI, диалоги A4 под admin и alice, запасные скриншоты в `assets/`.
2. Открыть `index.html`, нажать `P` — консоль докладчика. Пройти блоки A0–A7 по шагам: `J` / `K` — шаг, `C` — скопировать команду.
3. Проверить вживую: в A4 ответы под admin и alice различаются, в A5 есть оба отчёта «Выручка клиентов», в A6 сценарий доходит до «Применить».
4. Хотя бы раз запустить стенд из IntelliJ IDEA вместо `./demo up a`: проект `~/IdeaProjects/jmix-crm-stand`, run-конфигурация «Stand aura-light (OpenAI)». Если после этого `./demo check a` проходит, конфигурация рабочая.
5. Засечь каждый блок: таймера в runbook нет, план — минуты в повестке.

## 3. Репетиция демо B

1. `./demo up b` — PostgreSQL на `:5434` (и стенд для тизера B4). В IDE базу перед стартом поднимает сама «crm-from-db app».
2. Открыть `~/IdeaProjects/crm-from-db` в IDE, пройти B1–B4 по runbook. Ветки `b/02-model` … `b/05-agent` — готовые точки отката.
3. После прогона `./demo reset b` (или в IDE «crm-from-db database reset», приложение сначала остановить), затем один раз запустить «crm-from-db app» и создать пользователя `sales` / `sales`.

## 4. Только руками

Полный список с галочками — в [открытых вопросах](../../open-questions.md). Главное:

- **Скриншоты A3**: ответ Jmix AI в Studio и строка `CLI command:` из мастера CLI — в `assets/` под именами из [assets/README.md](../../../assets/README.md).
- **Шаги в Studio**: Generate Model from Database (B2), подписи фильтра (B2), путь Security → Resource roles (B3), инспекции (A2).
- **Площадка**: проектор или созвон, второй экран или зеркало — см. [Как вести демо → Второй экран или зеркало](usage.md#второй-экран-или-зеркало).

## 5. Накануне, после последней репетиции

1. `./demo reset` и `./demo prepare`: свежая база стенда без следов A6, заново записанные диалоги A4 и скриншоты.
2. `./demo reset b`, если демо B репетировали после предыдущего сброса.

## 6. В день показа

1. `./demo up a && ./demo check a`; перед демо B — `./demo up b`.
2. Открыть runbook, нажать `P`, перетащить окно сцены на проектор, `F`. Если проектор только зеркалит экран — вместо консоли панель `N`.
3. В консоли на pre-flight дважды нажать «Сбросить репетицию»: шаги начнутся с начала.
4. После показа — `./demo down`.

Если что-то пошло не так: `./demo status` — что где запущено, `./demo logs jpql` — какие запросы CRM AI отправил в базу, остальное — в [Как вести демо → Если что-то не так](usage.md#если-что-то-не-так).
