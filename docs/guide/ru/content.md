# Как править контент

Весь текст демо — слайды, заметки, шаги — лежит в одном файле `content.js`, в объекте `globalThis.DEMOS`. Код (`core.js`, `app.js`) при правке контента трогать не нужно. После каждой правки — `node --test`.

## Схема DEMOS

```js
globalThis.DEMOS = {
  a: { title: 'Демо A — AI × Jmix', blocks: [Block, ...] },
  b: { title: 'Демо B — Jmix с нуля', blocks: [Block, ...] },
};

Block = {
  id: 'A4',                    // уникален в демо, виден докладчику
  title: 'AI внутри приложения: CRM AI',
  minutes: 12,                 // план; у pre-flight — 0
  optional: true,              // необязательно: опциональный блок (штриховка в повестке, не входит в ядро)
  pre: true,                   // необязательно: pre-flight (первый блок демо)
  exit: 'Точка выхода №1: при отставании — …',  // необязательно
  flow: ['Вопрос словами', 'JPQL от модели', 'Валидация'],  // необязательно, 3–5 подписей
  slide: ['тезис для зала', ...],                // 3–6 тезисов; у pre-flight — 4–12 пунктов чек-листа
  notes: ['абзац заметок', ...],                 // для докладчика, минимум один
  actions: [{ kind: 'shell', text: 'curl -s …' }, ...],
};
```

Runbook ожидает ровно два демо с ключами `a` и `b`: на них завязаны клавиши `1` / `2` и переключатель в консоли. Название демо на сцене — часть `title` после последнего «—».

## Поля блока

| Поле | Где видно | Правила |
|---|---|---|
| `id` | счётчик и повестка консоли, панель зеркала | уникален в демо |
| `title` | заголовок слайда, повестка, «Далее» | коротко: длинное название переносится на слайде |
| `minutes` | ширина сегмента в повестке и на полосе сцены, «12′» в повестке, «Далее», суммы демо | целое; у pre-flight — 0 |
| `optional` | штриховка сегмента в повестке, метка «опц.» в карточке «Далее» | суммы считают ядро без опциональных блоков |
| `pre` | заставка на сцене, чек-лист в консоли | только у первого блока; `slide` — пункты чек-листа |
| `exit` | маркер в повестке, «выход» в карточке «Далее», строка под миниатюрой сцены | начинается с «Точка выхода…:»; консоль показывает текст после двоеточия |
| `flow` | полоса процесса на сцене под жёлтой чертой, над тезисами: подписи-чипы через стрелки | 3–5 подписей, каждая не длиннее 24 символов; полоса не по правилам не рисуется. Сейчас — у A4, A5, A6, B2 и B5 |
| `slide` | тезисы на сцене | 3–6 тезисов, каждый не длиннее 90 символов |
| `notes` | колонка заметок консоли: жирный лид и свёрнутый остаток | у каждого абзаца есть лид (см. ниже) |
| `actions` | колонка шагов консоли, «Далее», панель зеркала | `kind` из таблицы ниже, непустой `text` |

Тезисы стартуют с 32px при ширине сцены 1280 и ужимаются, если не помещаются, но не мельче 28px (`2.19cqw`). Полоса `flow` забирает часть высоты, поэтому после её добавления проверьте слайд скриншотом (см. [Проверка](#проверка)).

## Типы шагов

| `kind` | В консоли | Копируется |
|---|---|---|
| `shell` | моноширинно, «Терминал» | да |
| `git` | моноширинно, «Git» | да |
| `url` | ссылка, открывается в новой вкладке | да |
| `studio` | путь по меню Studio; стрелки « → » — точки переноса | нет |
| `say` | реплика для зала | нет |
| — (`prompt`) | вопрос модели; получается из `studio` после вводящей строки | да |

## Конвенции

Конвенции завязаны на русские фразы, потому что контент русский. Для контента на другом языке поменяйте `PROMPT_INTRO` и проверку «два промпта» в `classifyActions` в `core.js`.

**Короткая версия — метка `[8]`.** Метка в начале `text` делает шаг частью короткой версии: в интерфейсе — бейдж «8′», из копируемого текста метка убирается. `S` оставляет в блоке только такие шаги. Сейчас она есть у A6 (точка выхода №2).

```js
{ kind: 'studio', text: '[8] Шаг 1. AI-чат → вставить промпт из следующей строки → отправить' },
```

**Промпт — «промпт из следующей строки».** Вопросы модели не набирают на сцене. Шаг, в тексте которого есть «промпт из следующей строки», делает следующее `studio`-действие копируемым промптом; «два промпта» — два следующих. Промпт входит в короткую версию, если в неё входит вводящий шаг, поэтому `[8]` ставят только на вводящую строку.

```js
{ kind: 'studio', text: 'CRM AI → вопрос 1 живьём — промпт из следующей строки → строка executeQuery(jpql=…) в терминале' },
{ kind: 'studio', text: 'Сколько у нас клиентов и кто топ-3 по сумме заказов?' },
```

**Лид заметки.** Свёрнутый абзац в консоли начинается с жирного лида — кратчайшего законченного куска не длиннее 56 символов: первое предложение, кусок до «:», до « — » или до «)». Без лида абзац теряет жирное начало, и тест падает. Пишите абзац так, чтобы первая фраза называла тему: «Прогон и сброс накануне. …», «Агент и промпт A2. …».

**Тезисы слайда** — не длиннее 90 символов, без вводных; на сцене слова через дефис не переносятся, короткие предлоги держатся за следующее слово.

**Команды `jmix`** на сцене — всегда с `--no-update`, а pre-flight прогоняет ту же команду, что A3 (это проверяет тест).

**Где материалы.** Последний блок каждого демо (A7, B5) называет адрес репозитория на слайде; заставка pre-flight показывает его QR-кодом.

## Проверка

```bash
node --test
```

Тесты (`test/*.test.mjs`, без зависимостей) проверяют:

- контент: суммы минут (A 73 / 80, B 45 / 55), точки выхода, уникальность id, размер слайдов, длину тезисов, лиды заметок, промпты для вопросов модели, `--no-update`, ветки и стенд из spec, правила `flow`;
- логику `core.js`: состояние, шаги, короткую версию, повестку, синхронизацию, типографику;
- разметку `index.html`: нет внешних ресурсов, контраст текста не ниже 4.5:1, размеры шрифтов, справка `?` называет каждую клавишу из `app.js`.

Глазами — скриншотом нужного блока ([tools/shot.mjs](architecture.md#инструменты)):

```bash
node tools/shot.mjs index.html /tmp/a4.png '{"demo":"a","index":6}' 1280 720
```

`index` — номер блока в массиве демо, считая pre-flight с нуля (A4 — 6). Перед коммитом и перед демо — skill [runbook-verify](../../../.agents/skills/runbook-verify/SKILL.md).

## Свой runbook на основе этого

1. **Fork** репозитория и клон.
2. **Контент.** Заменить `content.js` своими демо `a` и `b`. Pre-flight — первый блок каждого демо.
3. **Тесты.** Общие правила в `test/content.test.mjs` (форма блока, размер слайдов, длина тезисов, лиды, типы шагов, лимиты `flow`) оставить. Правила этих демо заменить своими или удалить:
   - `test/content.test.mjs`: не меньше 6 блоков в демо, суммы минут, точки выхода A3, A6, B4 и опциональные A3+, B4, стенд `:8091` (без порта 8096), ветки из spec, конкретные промпты, команда A3 в pre-flight, jar стенда, A-pre (fallback'и A4–A6, прогрев Jmix AI), запасной скриншот A3, шаги A6, B1/B3, блоки с `flow`, название A5 как в карте A0, ссылка на материалы;
   - `test/html.test.mjs`: адрес под QR на заставке, viewBox символа QR `0 0 41 41`, ссылка GitHub в шапке консоли, `og:url` и `og:image`.
4. **Бренд.** Цвета — токены в `:root` в начале `index.html`: `--navy`, `--yellow`, `--pink`, `--pink-text`, `--green`, `--cyan`; текст — `--ink`, `--white`, `--muted`; фоны и линии — `--bg`, `--panel`, `--panel-2`, `--line`, `--line-hi`, `--code-bg`. Фон сцены — градиент в правиле `.stage`, её цвета — токены `--s-*` там же; светлая сцена — `.stage.light`. После замены `node --test` проверит контраст. Логотип — группы `#logo` и `#logo-mark` в SVG-спрайте в конце `index.html`.
5. **Адрес репозитория.** QR — символ `#qr-repo` в спрайте `index.html`. Сгенерируйте новый QR (дальше он работает офлайн):

   ```bash
   npx qrcode -t svg -o /tmp/qr.svg "https://github.com/<you>/<repo>"
   ```

   Из `/tmp/qr.svg` (вне репозитория, чтобы не закоммитить его) перенести `viewBox` и оба `<path>` в `<symbol id="qr-repo">`. Размер QR зависит от длины адреса: если новый `viewBox` не `0 0 41 41`, поменяйте это число и в `<svg class="h-qr">` в `app.js` (`stageHTML`), и в `test/html.test.mjs`. Старый адрес встречается в `app.js` (подпись под QR, ссылка GitHub в шапке консоли), `content.js` (последние блоки), `index.html` (`og:url`, `og:image`), тестах, README, руководствах, `AGENTS.md` и skills — в том числе строчными буквами (`fedoseew.github.io`). Найти все места:

   ```bash
   grep -rni fedoseew . --exclude-dir=superpowers --exclude-dir=.git
   ```
6. **Метаданные.** В `<head>` `index.html`: `<title>`, `description`, `og:title`, `og:description`, `og:url`, `og:image`.
7. **Ключ хранилища.** Все проекты одного пользователя на GitHub Pages живут на одном origin (`<you>.github.io`) и делят `localStorage`. Если runbook'ов несколько, поменяйте `STORAGE_KEY` в `core.js` и `DOCK_KEY`, `BEAT_KEY` в `app.js`.
8. **Язык интерфейса.** Подписи консоли, панели и справки — по-русски в `app.js` и `index.html`, названия типов шагов — `KIND_LABELS` в `core.js`; переводятся там же.

Пошагово для AI-агента — skill [runbook-adapt](../../../.agents/skills/runbook-adapt/SKILL.md). Skills лежат в `.agents/skills/`, в `.claude/skills/` — символьные ссылки на них. На Windows включите ссылки до клонирования (`git config --global core.symlinks true` в режиме разработчика) или скопируйте `.agents/skills/*` в `.claude/skills/`: иначе Git создаст вместо ссылок текстовые файлы и Claude Code не увидит skills.

## Публикация на GitHub Pages

1. Settings → Pages → Build and deployment → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)` → Save.
2. Через минуту-две сайт доступен по адресу `https://<you>.github.io/<repo>/`. Файл `.nojekyll` в корне отключает Jekyll: файлы отдаются как есть.
3. Обновить `og:url` и `og:image` в `index.html` под новый адрес.

Сборки нет: что лежит в `main`, то и опубликовано.
