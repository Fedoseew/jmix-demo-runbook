# Jmix Demo Runbook — дизайн

Дата: 2026-10-07. Статус: на ревью.

## 1. Цель

Два офлайн-демо Jmix для одного заказчика, две аудитории:

- **Группа A** — разработчики с ~годом опыта на Jmix. Тема: AI при разработке на Jmix и AI внутри Jmix-приложений. 60–90 минут.
- **Группа B** — разработчики, только начинающие с Jmix. Тема: что такое Jmix, где уместен, как создать проект, быстрое приложение из существующей БД. 40–60 минут.

Успех: минимум живой генерации кода на сцене, каждый шаг заранее подготовлен в ветке/стенде, переключение между шагами без пауз, у докладчика под рукой заметки, команды и таймер.

Деливерабл этой итерации: **план обоих демо + локальный HTML-runbook**. Демо-репозитории и ветки — следующая итерация (раздел 7 фиксирует, что именно).

## 2. Опорные факты (проверено локально 2026-10-07)

- `jmix-crm` `main` — Jmix 3.0.3, add-ons: aitools, reports, audit, appsettings; Spring AI OpenAI. Workspace «CRM AI» уже есть. Toolkit установлен (`.skills`, `.claude`, `.junie`, `.agents`).
- `jmix-crm` ветка `50-dynmodel-ai-agent` (tabbed-вариант не используем) — Jmix + Jmix Premium `3.1.999-SNAPSHOT` из local Maven. Add-ons: aitools, aichat, dynmodel, dynmodel-ai. Стенды `aura-light` :8091 … `aura-rtl` :8095 (используем `aura-light`; `aura-dark` :8092 — на Claude при `ANTHROPIC_API_KEY`), `OPENROUTER_API_KEY` (опц. `ANTHROPIC_API_KEY`), логин `admin/admin`, `demo/dynmodel-ai-agent/README.md` с готовыми сценариями.
- Reports band type **AI-generated JPQL** (`DataSetType.LLM`) — только в Jmix master (3.1), в 3.0.3 нет. Промпт → JPQL генерируется при авторинге через Text-to-Data Query из aitools, одна попытка исправления, запрос сохраняется с отчётом; запуск отчёта выполняет сохранённый JPQL через `DataManager` с правами текущего пользователя, модель на запуске не нужна.
- aitools data-load: генерация + валидация JPQL, проверка READ на весь граф запроса, row-level policies, `@ExcludeFromAi`, `@Secret`, non-persistent атрибуты скрыты.
- `jmix-agent-toolkit`: 22 skills (`content/skills/*`), guidelines-block, install wizard (CLI `install.sh` и Studio 3.0+ «AI Agents Toolkit»), регистрация MCP, Playwright.
- `jmix-cli`: wizard, те же шаблоны что Studio, bundled JRE. Локально `jmix --version` зависает — проверить до демо.
- CRM работает на HSQLDB file (`.jmix/hsqldb/b2b-crm`) — для reverse engineering заменяем на PostgreSQL в Docker с дампом.

## 5. HTML-runbook

### 5.1 Ограничения

- Одна папка, три файла: `index.html` (разметка + CSS), `app.js` (логика + DOM), `content.js` (объект `DEMOS`). Открывается с диска (`file://`), **ноль внешних запросов** (офлайн-зал). Системные шрифты.
- Контент — `globalThis.DEMOS` в `content.js`, правится руками, проверяется тестом `node --test`.
- Тёмная тема, крупный шрифт под проектор (слайд ≥ 28px, заметки ≥ 18px).
- Клавиатурная навигация обязательна; контраст текста ≥ 4.5:1.

### 5.2 Модель данных

```js
DEMOS = {
  a: { title, blocks: [Block] },
  b: { title, blocks: [Block] }
}
Block = {
  id: 'A2', title, minutes, optional?: true, pre?: true, exit?: 'текст точки выхода',
  slide: ['буллет', ...],          // 3–6, крупно, для зала; у pre — 4–12 пунктов чек-листа
  notes: ['абзац', ...],           // заметки докладчика
  actions: [Action]                // что делать руками
}
```

`shell`/`git` — моноширинно + кнопка copy; `url` — ссылка (открывается в новой вкладке); `studio` — путь по меню Studio; `say` — ключевая фраза.

### 5.3 UI

- **Шапка:** переключатель A/B; таймер текущего блока (план → обратный отсчёт, красный при перерасходе); сумма план/факт по демо.
- **Слева:** список блоков: номер, название, минуты, бейдж «опц.», маркер выхода. Клик — переход. Активный подсвечен.
- **Центр:** слайд: заголовок + буллеты.
- **Режим докладчика** (клавиша `N`): под слайдом заметки и действия с copy-кнопками. Проектор зеркалится, поэтому синхронизация двух окон не делается.
- **Клавиши:** `←`/`→` блок, `N` заметки, `T` таймер старт/пауза, `R` сброс таймера блока, `F` fullscreen, `1`/`2` демо A/B.
- **localStorage:** текущее демо, блок, состояние таймера, флаг заметок. F5 не сбивает. Чтение/запись в try/catch.
- Copy: `navigator.clipboard`, fallback — выделение текста. `file://` в Chrome — secure context, работает.

### 5.4 Что сознательно не делаем

Синхронизация окон, анимации/переходы, печать, экспорт, подсветка синтаксиса, внешние библиотеки.

### 10.2 Синхронизация окон

Общее состояние уже лежит в `localStorage` (`jmix-runbook/v1`). Второе окно слушает событие `storage` и перерисовывается. Проверено в Chromium на `file://`: событие `storage` и `BroadcastChannel` доходят, прямой доступ к `window.opener` заблокирован (opaque origin). Используем `storage`.

Общее состояние: демо, блок, позиция в каждом демо (`indexByDemo`: случайное `2` → `1` из любого окна возвращает на тот же блок, демо, открытое впервые, начинается с pre-flight), таймер, факт по блокам, шаг по каждому блоку, короткая версия, светлая сцена. Состояние старых версий без `indexByDemo` читается. Своё у окна: вид (из URL), открыта ли панель (`sessionStorage` вкладки), отметки чек-листа.

Пульс: окно сцены раз в 2 с пишет время в `jmix-runbook/stage`; консоль считает сцену открытой, пока пульсу меньше 6 с. Если `localStorage` недоступен, окно пишет об этом (и на сцене): второе окно не синхронизируется, F5 вернёт к началу.

### 10.3 Клавиши (по `event.code`, работают в русской раскладке)

| Клавиша | Действие | Где |
|---|---|---|
| `←` / `→` | блок | везде |
| `1` / `2` | демо A / B | везде |
| `T` | таймер старт / пауза; в течение 3 с после `R` — отмена сброса | везде |
| `R` | сброс таймера блока на паузу; `R` или `T` за 3 с возвращают время и ход таймера | везде |
| `F` | полный экран | везде |
| `P` | открыть консоль в новом окне | сцена |
| `N` | панель для зеркала | сцена |
| `J` / `Space`, `K` | следующий / предыдущий шаг | консоль; сцена с открытой панелью |
| `C` | копировать текущий шаг; на реплике и шаге Studio — сообщение, что шаг не копируется | консоль; сцена с открытой панелью |
| `S` | короткая версия (шаги с меткой `[8]`) | консоль; сцена с открытой панелью |
| `L` | светлая сцена | везде |
| `?` (`/` с `Shift` или без) | справка по всем клавишам; `?`, `Esc` или щелчок мимо закрывают | везде |

Автоповтор зажатой клавиши игнорируется. С `Ctrl`, `Alt`, `Cmd` и в полях ввода клавиши не перехватываются, `Space` — на кнопках, ссылках, заметках и чекбоксах. На сцене без панели `J`, `K`, `C`, `S` не действуют.

### 10.4 Шаги

- Действие `studio` после строки «… промпт из следующей строки …» становится шагом-промптом с копированием; «два промпта» — двумя.
- Метка `[8]` в начале текста — шаг короткой версии; в интерфейсе метка показывается бейджем «8′», из копируемого текста убирается. Промпт входит в короткую версию, если в неё входит вводящий его шаг.
- В короткой версии `J`/`K` пропускают остальные шаги.
- Щелчок по кнопке копирования шага текущего блока делает этот шаг текущим.
- Контент (проверяет `node --test`): каждый вопрос к модели (CRM AI, Jmix AI, дизайнер отчётов) — шаг-промпт; каждый запуск `jmix` — с `--no-update`; у каждого абзаца заметок есть лид для консоли (предложение, «…:» или кусок до « — » не длиннее 56 символов); тезис слайда — не длиннее 90 символов.

### 10.5 Ограничения

- Файлы: `index.html` (разметка, CSS, SVG-спрайт), `core.js` (чистая логика, тесты в Node), `app.js` (DOM). Порядок подключения: `content.js`, `core.js`, `app.js`. Не загрузился `content.js` или `core.js` — страница пишет причину вместо пустого экрана; в `core.js` нет lookbehind (Safari до 16.4 уронил бы файл целиком).
- Ноль внешних запросов; системные шрифты; работает с `file://`.
- Палитра Jmix: `#17124B`, `#FDB42B`, `#FC1264`, `#41B883`; текст `#DBDDE1`. Контраст текста ≥ 4.5:1 на фонах консоли и светлой панели.
- Сцена: тезисы ≥ 28px при 1280. Консоль показывается только докладчику: текст ≥ 14px. Панель зеркала и справку `?` видит зал: текст ≥ 18px.
- Обращения к `localStorage`, `sessionStorage`, буферу обмена, fullscreen и `window.open` — в `try/catch` или с проверкой результата. Без `console.log`.
- Не делаем: сохранение отметок чек-листа между перезагрузками, время старта на заставке, синхронизацию раскрытых заметок, перерасход в панели зеркала.

### 10.6 Таймер

- Таймер встаёт на паузу только по `T`. При переходе между блоками (`←`/`→`, `1`/`2`, щелчок по повестке) время блока уходит в факт; идущий таймер продолжает на новом блоке с его факта, стоящий остаётся на паузе.
- Сам таймер стартует только при переходе с pre-flight на первый блок того же демо. Щелчок по повестке с pre-flight на другой блок и возврат `1`/`2` через pre-flight другого демо его не запускают. На pre-flight таймер стоит.
- Блок, пройденный быстрее 30 с, факта не получает и в темп не идёт: пропущенный опциональный блок не даёт ложного запаса.
- Темп («План», «Факт», «Отстаём» / «Запас») — по блокам с фактом плюс текущий блок.
